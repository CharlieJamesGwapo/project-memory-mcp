# Setup and context confidence upgrade

The user requests continued autonomous improvement after v0.2.1, retaining a free local Rust product. Engineering choices below are proposals selected under that delegated scope; no new cloud/model account, filesystem crawler or agent runtime is introduced.

## Evidence and approaches

Read-only product audit confirmed that first archive creation requires an MCP handshake, standalone inspection is absent, Studio exposes raw numeric caps, and docs/studio.md retains outdated distribution wording. A synthetic eight-client simultaneous-start probe reproduced startup failures in three of fifteen rounds, including a false foreign-database error. Existing literal retrieval is correct, but a task's words spread across fields cannot match a single phrase.

Considered: (1) embeddings/cloud sync, with new privacy/cost and migration boundaries; (2) FTS5 persistent indexing, with a schema/index lifecycle and read-only compatibility design; (3) improve existing deterministic local workflows with no schema change. Choose (3). Official SQLite FTS5 documentation confirms its table/index lifecycle; no FTS index or semantic-search claim belongs in this release. Agent Skills evaluation guidance supports versioned fixtures and separate behavioral checks rather than relying on structural validation alone.

## Goals and scope

1. Serialize writable archive identity checks and schema creation, then configure WAL outside the transaction using bounded BUSY/LOCKED handling. Preserve foreign/newer database rejection before persistent changes, schema1, rollback, and five-second SQLite lock waits. Test concurrent fresh starts and existing foreign files.
2. Explicit CLI `init`, `projects`, `search`, `record`, `context`. No subcommand continues to mean MCP stdio. Read commands always open existing archives read-only, require project UUIDs, reuse Store::execute and typed validation, and never create a missing archive. Init is explicit/idempotent, may initialize an empty archive, preserves existing records and rejects --read-only/foreign/newer/symlink paths. JSON for projects/search/record; context defaults Markdown and supports --json. CLI content on stdout, errors stderr/nonzero. Doctor and print-config remain compatible. The context cap still measures canonical MCP result bytes, independently of pretty JSON/Markdown CLI output.
3. Optional `get_context_bundle.query_mode` enum literal(default)/terms. Search tools remain literal, same schemas otherwise. Terms requires query and excludes record_ids. Extract distinct Unicode-alphanumeric runs, ASCII-fold only, keep input order, accept1..8 terms; query length remains1..2000. A record matches if any term is a literal substring in existing human-text fields. Rank whole project before the 200-candidate cap by distinct matched-term count descending, headline-term count (title/decision/summary) descending, insertion seq descending. Exclude superseded decisions, sources, IDs and authorship as before. Whole records, canonical result cap, omission repair and atomic explicit selection are unchanged. Terms outputs selection.mode='terms', selection.query_terms, selection.ranking='term_coverage_then_headline_then_recency'; records selection_reason='ranked_term_match', matched_terms:string[]. Existing literal/recent/explicit shapes and ordering stay unchanged. Bound SQL fragments; bind every query value. No linguistic stemming, embeddings, confidence scores or universal relevance claims.
4. Studio Small(8000bytes/4records), Balanced(16000/8 default), Expanded(32000/12) presets and Custom advanced numeric caps. Presets change settings only; never retrieve/apply automatically. Optional explicit phrase/terms control for a nonempty task. Browser samples model the same ranking/limits and are synthetic. Preserve stale-response and project/session guards, manual brief selection, explicit Add/Replace, full records and native read whitelist. Distinguish no candidates from candidates omitted by budget.
5. Add focused debugging and verification references to the existing one-entry skill, retaining four installed folders and progressive loading. Preserve host capability/permission gates and historical-evidence boundaries. Provide versioned behavioral fixtures and a deterministic real-MCP retrieval evaluation with machine-readable bytes/coverage/omission results; report synthetic scope, not billed-token savings.
6. Correct setup/Studio/API/architecture documentation, add CLI examples/evaluation guide and release notes. Release0.3.0 with unchanged schema1 after complete validation; preserve all existing versioned assets and publish exact attested metadata at its release tag.

## Acceptance and boundaries

- Reproduce the startup failure before patch; repeated parallel clients all handshake and retain their writes after patch. No adoption or byte changes to foreign/newer fixtures.
- CLI reads on missing/symlink/foreign archives fail without creating the main archive; init exits without handshake; UUID isolation/cursors/full-record output persist.
- Terms tests cover distributed fields, older high-coverage before >200 newer weak matches, headline/recency ties, duplicate and Unicode terms, punctuation-only/excess terms, source-only nonmatches, superseded/project isolation, exact cap/omissions and readonly operation.
- UI tests cover exact preset requests, Custom edits, no implicit retrieval/apply, terms validation, matching sample semantics, distinct empty cases, stale results; actual native workflow checked after serial dist/embed builds.
- Skill validation plus independent behavioral scenarios; evaluation report must fail on missing required fixtures, overshoot, truncated full records or cross-project leakage and label coverage tradeoffs.
- Full relevant Rust/native/frontend/Python suites, Clippy/fmt, source/package/docs checks, advisory evidence and independent final review. Public downloaded MCPB smoke, Studio strict signature ZIP round trip, checksums/provenance and Registry readback.
