# Project Memory MCP 0.5.0

Guided setup, visible review history and read-only memory health, retaining
SQLite schema 1 and the existing local security defaults.

## Added

- Shared setup preview and CLI `setup`: inspect explicit archive/executable/policy
  paths, preserve restrictions in generated JSON and provide actionable next steps.
  The executable is not run, and client settings, memory and audit logs are not changed.
- Studio Guided Setup with explicit preview/copy, plus Reviews and Health tabs,
  bounded pagination, supplied-head input and stale-response guards.
- Full structured review metadata retained in Studio context exports.
- `get_memory_health` and CLI `health`: snapshot counts, complete per-record
  assessments and evidence-based review suggestions within a canonical byte cap.
- Two project resource templates and three workflow prompts with tool fallbacks,
  policy-enforced reads, bounded outputs and private cache hints on modern peers.
- Legacy and current protocol tests, updated setup/health/API/architecture guides
  and progressive workflow guidance.

## Upgrade

Existing supported archives need no migration. Default writable discovery is
15 tools, explicit deletion opt-in exposes 16, and read-only exposes ten.
Operation policies can reduce these counts. Add `get_memory_health` to an explicit
allowlist when desired. Resources reuse the permissions of their underlying tools.
Studio remains a separate local read-only connection; a setup policy preview does
not apply a policy to Studio or modify another client's configuration.

## Evidence boundaries

Health signals do not infer semantic conflicts, certify safety, inspect a Git
repository or repair records. Freshness compares supplied commit IDs. Resource
views are bounded first pages. Prompts return instructions rather than running
workflows. Setup readiness is limited to its stated local checks; executable
authenticity/version and actual client compatibility are untested by preview.

SQLite may maintain WAL/SHM coordination files during read-only inspection.
Archives/backups remain plaintext. Policy is not authentication against a local
file owner, cursor metadata exposes insertion activity, and audits/SQLite are
not an atomic cross-file transaction. The macOS arm64 Studio preview retains
ad-hoc signing without Developer ID/notarization; upstream desktop warnings are
documented in [security](../security.md). Checks/provenance are scoped evidence,
not a guarantee of malware absence.
