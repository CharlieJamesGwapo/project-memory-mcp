Thirty rounds of eight simultaneous actual MCP clients completed with no startup
failures after the initialization fix. Independent review found additional edge
cases; regressions reproduced them before fixes. Foreign/newer committed WAL
refusals now preserve main/WAL bytes, and a lock released beyond the shared
startup contention budget no longer permits late successful initialization.

The evaluator now rejects shared serializer omissions of timestamps/provenance
and incomplete matched-term explanations instead of trusting a deficient seed
response as its reference. Actual negative protocol shims were rejected while
the honest server passed. The versioned corpus covers six synthetic projects,
214 records and five cases in both modes over 232 requests. Its SHA-256 is
`de34f6570373dd8a0f4c88c43ecc9a779c0768e1b773121391ec2fb0cdb3db4e`.
This is a protocol/selection regression receipt, not a universal quality, model
usage or billing benchmark. Terms can return more evidence and more bytes.

Studio's committed Unicode table is checked against every valid scalar and the
pinned Rust Unicode version. Actual macOS WKWebView probes now match MCP for the
previously rejected and mixed Unicode terms. Browser-preview interaction checked
Small limits, opt-in terms, matched terms, explicit Add, Custom changes and brief
preservation using labeled synthetic data. The native bridge, embedded production
assets and signed build passed automated checks. A full native window click-through
could not be completed because computer-use access remained unavailable; browser
preview success is not described as native interaction or other-OS runtime proof.

The debugging/verification skill scenarios met the same criteria with the previous
and revised packs; no behavioral superiority is inferred. See
[skill evaluation](../skill-evaluation.md) for receipts and the genuinely
tool-disabled scenario that remains unrun.
