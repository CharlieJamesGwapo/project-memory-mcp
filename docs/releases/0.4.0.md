# Project Memory MCP 0.4.0

Local security controls and commit-linked code review, preserving SQLite schema 1.

## New

- Optional strict local access policy restricts project UUIDs and operations in
  Store, filters discovery/project lists/diagnostic counts, and survives print-config.
- Deletion is disabled by default. A local policy must explicitly enable it;
  model-controlled `confirm:true` still does not establish human authorization.
- Narrow credential screening rejects matching writes/exports by default;
  sanitized inspection reports help find previously stored credentials.
- Optional metadata audit receipts record attempts and outcomes without memory
  text. Archive/sidecar destinations are refused; cross-file atomicity is not claimed.
- `save_review` and `get_review_history` preserve structured findings, exact
  commits, actual checks, immutable revision history and supplied-head freshness.
- `get_access_policy`, CLI `policy`/`inspect-secrets`, and policy-preserving config.
- Six new focused workflow references: test planning, dependency review, safe
  refactoring, release readiness, memory hygiene and architecture review.
- Temporary-copy backup recovery verification with bounded waits and sanitized reports.
- Updated setup, API, review, security, backup, architecture and workflow guides.

## Upgrade

Existing schema-1 archives need no migration. Reviews are ordinary immutable note
records with additional structured metadata; existing retrieval/Studio can read them.
Default discovery is 14 tools, or 15 with deletion enabled; read-only exposes nine.
Policies can further reduce these counts. Discover actual host schemas before use.
Clients that relied on deletion must explicitly configure local policy.

## Scope

Local archives/backups remain plaintext. Policy is per-connection capability
restriction, not authentication; file owners can access the archive outside it.
Global-sequence cursors expose activity metadata. Credential patterns are incomplete,
and ordinary authorized reads preserve complete records. The server does not execute
code review, inspect Git, run checks or provide models/agents; the host supplies them.

Studio remains a read-only macOS arm64 preview with ad-hoc signing, without Developer
ID/notarization. Existing Linux desktop dependency warnings remain documented.
See [security](../security.md) for current evidence and limits. Checksums/provenance
provide scoped artifact evidence, not a malware-free guarantee.
