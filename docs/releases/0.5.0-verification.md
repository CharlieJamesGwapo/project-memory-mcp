## Boundaries

Setup checks explicit local paths and archive diagnostics without executing the
server or certifying executable authenticity/version/client compatibility. It
preserves policy/read-only flags, does not initialize an archive or audit log,
and does not change client settings. Normal SQLite read-only inspection can
maintain WAL/SHM coordination files.

Health uses supplied historical metadata, not semantic conflict inference,
repository inspection, automatic repair or safety certification. Review freshness
compares supplied commit IDs. Resource views are bounded first pages; prompts
return instructions rather than retrieving records or executing workflows.

Archives/backups remain plaintext. Policy is per-connection capability restriction,
not authentication against a local file owner. Global-sequence cursors disclose
activity metadata, and audit/SQLite commits are not a cross-file atomic transaction.
Authorized ordinary reads preserve existing records, including possible sensitive
text; credential screening is incomplete. Studio remains a macOS arm64 preview
with ad-hoc signing, without Developer ID/notarization. Compile/test CI does not
prove interactive behavior on every OS. See [security](../security.md),
[setup](../setup.md), [memory health](../memory-health.md) and [MCP views](../mcp-views.md).
Checksums, advisory scans, source review and provenance provide scoped evidence,
not malware absence or a guarantee of future safety.
